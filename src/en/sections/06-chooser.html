06 / PICK YOUR NEXT MOVE

Choose a starting point for your task

These suggestions synthesize the research. Use only the paths allowed by your project's rules and permissions.

Bug fix: establish the reproduction steps first

① Context to provide

Observed symptoms, steps to reproduce, expected behavior, relevant versions and logs.

② Results to verify

The problem no longer occurs with the same steps, and related user flows still work.

③ Process to trim

For a narrow bug, do not start with broad architectural changes or several review agents.

Artifact to keep · Cause → change → execution evidence → unverified scope

Start with a small change

  1. 1
    Change one part of your completion report

    Separate code changes, runtime rollout, observations and unverified conditions.

  2. 2
    Map one real feature

    Connect its entry point, prerequisites, actions and expected results.

  3. 3
    Prevent one recurring failure

    Choose the smallest suitable change to structure, rules or tools.

Check before installing anything new

First check whether your current tools and skills can solve the problem. Read the instructions a skill adds, its automatic actions, its costs and its permissions to make changes.

If a repository restricts test creation, use UI observations, logs, data and permitted checks to define what you can verify. Follow each repository's own procedures.
