## 담당 AI와 작업 AI의 역할 분리

- 작성자의 [위임 구조 8판 글](https://seosoyoung.eiaserinnys.me/posts/opus-card-assignee-delegation-v8/)은 11월 12일 작성으로 표시되며 페이지 메타데이터는 10:30 KST다. 담당 AI가 기준을 정하고, 다른 세션이 조사·구현·수습·배포 확인을 담당하며, 변경분·종료 코드·원출력을 모은 꾸러미를 담당에게 전달한다고 설명한다. 검증 스크립트의 통과는 최종 합격이 아니라 담당 검수 준비 신호다.
- 기존 담당의 검수 55턴과 서로 크기가 같지 않은 시범 세 카드의 23턴을 비교한 값은 검수 입력 중앙값 2.85M→0.55M 토큰이다. 글은 읽기 전용 검수 보조 에이전트의 입력을 포함한 평균도 5.33M→1.06M으로 보고한다. 두 값의 분모와 통계량을 섞지 않는다. 이 비교는 다른 하위 작업자의 전체 사용량, 실제 청구 비용, 장기적 품질 우열을 입증하지 않는다.
- 작성자는 결함이 남은 꾸러미를 시험용 새 담당이 한 번 반려한 사례를 설명하지만, 반려 이후 수정·재검수 전체 흐름과 화면 작업은 아직 시범하지 않았다고 밝혔다. 작업 크기와 난이도를 맞춘 비교나 독립 재현도 없다.
- [Reddit의 다른 대형 프로젝트 사용자](https://www.reddit.com/r/ClaudeCode/comments/1xvlvos/reducing_usage_on_very_large_mloc_projects/)는 11월 14일 07:32:45에 계층형 계획·구현·검토 에이전트의 한도 소진과 연결된 하위 세션이 쉬는 동안 상위 세션이 재호출되는 경험을 보고했다. 제품 동작이나 원인을 독립 재현하지 않았고, 작성자가 해결법을 찾지 못한 것은 해결법이 없다는 증거가 아니다.

## Claude Code 공식 자료와 이전 해석 변화

- [Code Mode 공식 문서](https://code.claude.com/docs/en/code-mode)는 11월 13일 조사 당시 404였으나 이번에는 본문을 읽을 수 있었다. 최초 게시·개정일은 확인하지 못했다. 문서는 기본 꺼진 실험 기능으로 설명하며 2.1.323 이상 대화형 터미널을 요구한다. Desktop, Agent SDK, `-p`, 에이전트 팀과 원격 연결 등은 지원하지 않으며, 이 모드로 시작한 세션은 터미널에서 모드를 켠 채 재개해야 한다고 한다. 자동 모드 분류기는 코드 단위를 보고 실행 중 계산되는 값을 보지 못한다. 별도 거부·확인 규칙과 `PreToolUse` 훅은 도구 호출에 적용된다고 설명한다. 사용자 세션에서는 시험하지 않았다.
- [Claude Code 2.1.325 릴리스](https://github.com/anthropics/claude-code/releases/tag/v2.1.325)는 11월 14일 05:40:01에 게시됐다. 비정상 종료 뒤 재개한 세션에서 최근 턴이 누락되는 경우와 Windows 경로의 드라이브 문자 대소문자·구분자 차이 때문에 `/resume`이 거부하거나 세션을 숨기던 경우를 수정했다고 한다. Code Mode의 worktree 경로와 재개 뒤 자동 시작 사례도 별도로 수정했다고 한다.
- 같은 릴리스는 샌드박스 Bash가 기본 권한 흐름을 따르도록 바꾸고, 예약 작업과 `/loop`가 `allowed-tools` 또는 훅을 선언한 스킬을 실행하기 전에 확인한다고 설명한다. 자동 작업이 실제로 대기할지는 사용 중인 버전·설정과 권한에 달렸다. 현재 사용자 환경은 시험하지 않았다.
- 개인정보 모듈의 [이전 README](https://github.com/anthropics/claude-code/blob/90380efca7f9d73e206fac453f841b6acd664f4d/mods/privacy/README.md)와 11월 14일 06:52:54에 개정된 [현재 README](https://github.com/anthropics/claude-code/blob/678bca6d141fb69feb451013e055234a2085aeff/mods/privacy/README.md)를 비교했다. 이전은 일부 셸 입력만 설명했고, 현재 문서는 일부 실행 스크립트와 쓰기·편집, WebFetch URL 및 조건에 맞는 MCP 입력을 추가로 설명한다. 다만 WebSearch·브라우저 도구와 실행 중 계산 값 등 빠지는 경로가 남고 문서 자체도 보안 경계가 아니라고 밝힌다. 모든 이메일이나 비밀을 막는다는 뜻은 아니다. 2.1.325 릴리스는 이메일 검사 개선을 별도로 설명한다. 문서상 모듈 활성 조건과 실제 사용자 세션 동작은 확인하지 않았다.
