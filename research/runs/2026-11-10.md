## 버전과 기존 설명의 변화

- [Claude Code 2.1.321 릴리스](https://github.com/anthropics/claude-code/releases/tag/v2.1.321)는 11월 10일 KST다. Remote Control의 `Queue for later` 메시지가 현재 턴 중간에 도착하던 경우, auto mode에서 압축 전 시작된 일부 배경 에이전트 보고가 유실되던 경우, MCP OAuth 리디렉션으로 비밀이 다른 호스트에 전송되던 경우 등을 수정했다고 설명한다. 특정 기능의 릴리스 설명이며 이슈 댓글을 포함한 모든 대기열의 보장이나 직접 재현 결과는 아니다.
- 이전 [변경 이력 개정](https://github.com/anthropics/claude-code/blob/0ed94698aa0aeee471465fc9c867c2e8434c4d68/CHANGELOG.md)은 2.1.317에서 웹 또는 셸의 계정 이메일 전송에 확인을 추가했다고 기록했다. [새 개정](https://github.com/anthropics/claude-code/blob/a4fcccc70a89df6607e66cc30682d551269d0680/CHANGELOG.md)의 2.1.321은 계정 이메일과 User-Agent가 함께 있는 셸 명령만 확인 없이 거절하도록 바뀌었다고 설명한다. [공개 개인정보 모듈](https://github.com/anthropics/claude-code/blob/90380efca7f9d73e206fac453f841b6acd664f4d/mods/privacy/README.md)과의 범위를 함께 읽었다. 별도의 다른 보호 기능이나 이메일이 모델 맥락에서 제거됐는지는 이 항목만으로 확인할 수 없다. 실제 동작을 재현하지 않았다.
- [OpenSpec 1.17.0 릴리스](https://github.com/Fission-AI/OpenSpec/releases/tag/v1.17.0)는 11월 10일 KST다. 0.12 이후의 기존 프로젝트를 한 번에 업데이트하고, 수정하지 않은 생성 파일은 정리하되 수정한 파일은 보존한다고 설명한다. 명령 파일 제거는 2.0의 계획이며 스킬은 유지할 예정이라고 한다. 업그레이드를 실행하지 않았다.
- [Aether의 이전 README](https://github.com/PrashnaLabs/aether/blob/d44718aa07eecfc9d8093042bf010fa092dc972b/README.md)와 [11월 9일 KST 개정](https://github.com/PrashnaLabs/aether/blob/44b517a4b13280909718cbe527b8068f00fff9f6/README.md)을 비교했다. 보고 있지 않은 대화의 완료·응답 요청 알림과 같은 대화·종류의 10초 반복 제한, 기본 비활성인 webhook 설명이 추가됐다. webhook은 제목·본문·대화·상태를 보낸다고 기술한다. [기존 알파 릴리스](https://github.com/PrashnaLabs/aether/releases/tag/alpha-0.1.0)는 이 개정보다 이전이며 해당 배포에 새 기능이 포함됐는지와 다중 PC 복구는 미확인이다.

## 비용과 검증의 조건

- [Fable 5.2 공식 API 문서](https://platform.claude.com/docs/en/models/fable-5-2/overview)는 출시일을 11월 9일로 표기하며 시간대는 확인하지 못했다. 기본 API 가격은 입력·출력 각각 백만 토큰당 $8·$40다. `tool_choice`의 `any`와 `tool`은 400 오류이며, 명시적으로 승인된 예외를 빼면 30일 데이터 보존이 필요하다고 적혀 있다. API 조건을 Claude 구독 사용량으로 일반화하지 않는다. 11월 10일 KST [Addy Osmani의 답글](https://x.com/addyosmani/status/2119907165007945813)은 자체 시험에서 토큰 단가는 20% 낮아도 더 많은 토큰 사용으로 작업당 비용이 이전 모델과 대체로 비슷했다고 설명한다. 과제 구성·편차는 공개되지 않았으며 직접 측정하지 않았다.
- 11월 9일 KST의 [사용량 우려](https://x.com/ASaltyVet/status/2119530707026653650)에 대한 [poteto의 답변](https://x.com/poteto/status/2119607350453776677)은 코드를 통한 결정적 검사가 장기적으로 토큰을 아낄 수 있다는 예상이다. 생성·유지·실패 조사와 실행 시간까지 포함한 비교 실험은 제시하지 않았다. 전판의 형식 검증 제안 및 사용량 제약과 함께 보되 검증된 절감량으로 취급하지 않는다.
