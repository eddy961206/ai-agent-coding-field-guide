05 / VERIFY THE RIGHT THING

실행 검증과 형식 검증은
서로 다른 질문에 답해

EMPIRICAL / 실행에서 확인

이 환경에서 실제로 작동했나?

사용자 흐름, 실제 API와 데이터, 성능 측정, 허용된 테스트. 코드와 제품이 지금 어떤 행동을 하는지 관찰해.

남는 범위: 실행하지 않은 입력·타이밍·권한·환경에서는 다른 일이 생길 수 있어.

FORMAL / 명세와 가정에서 확인

이 모델·조건에서 성질이 성립하나?

상태 전이·동시성·불변 조건을 명시하고 모델 탐색이나 증명 도구로 확인해. 도구와 방법마다 다루는 범위가 달라.

남는 범위: 명세 자체가 틀렸거나 코드와 모델이 다를 수 있어. 한정된 탐색은 그 한계 밖을 보장하지 않아.

가상의 상태 모델 예시

화면 전환 중 늦은 응답이 오면?

실행된 모델 검사 결과가 아닌 설명용 도식이야. 실제 구현에서는 취소·재시도·재연결 등 포함할 사건을 별도로 결정해야 해.

완료 보고에서 확인할 네 줄

  1. 검사한 성질: 늦은 응답이 현재 화면을 덮지 않는다.
  2. 검사 범위: 모델의 상태·동시 요청 수·탐색 제한·가정.
  3. 코드와의 연결: 구현 위치와 모델 전이의 대응.
  4. 실제 관찰: 허용된 환경에서 재현한 순서와 결과.
“모델에서 문제를 찾지 못함”과 “제품에 버그가 없음”은 다른 결론이야. 상태도는 사용자 의도를 검토할 자료로도 유용해.
